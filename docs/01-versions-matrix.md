## 2. Java: какую JDK ставить

| Диапазон Minecraft | JDK для компиляции и запуска |
|---|---|
| 1.16.5 и ниже | 8 (некоторые тулчейны — 11) |
| 1.17 – 1.17.1 | 16 |
| 1.18 – 1.20.4 | **17** |
| 1.20.5 – 1.21.11 | **21** |
| 26.1 и выше | **25** |

Почему так: с 1.20.5 Mojang поставляет игрокам Java 21, а с 26.1 — Java 25, и ванильный код
использует новые языковые возможности (например, [JEP 447](https://openjdk.org/jeps/447) —
операторы до `super()` в конструкторах). Компилировать мод под более высокий байткод, чем
у целевой версии игры, нельзя — мод просто не загрузится.

Для 26.1+ нужна и свежая IDE: IntelliJ IDEA ≥ 2025.2, Eclipse ≥ 2025-12
(или 2025-09 + плагин Java 25 Support).

В Gradle это выражается двумя разными способами:

```groovy
// Fabric (Loom): жёсткая планка байткода
tasks.withType(JavaCompile).configureEach { it.options.release = 21 }

// NeoForge (ModDevGradle): тулчейн, Gradle сам скачает нужную JDK
java.toolchain.languageVersion = JavaLanguageVersion.of(21)
```

## 3. Схема версий Minecraft после 2025 года

Mojang отказалась от `1.x.y`: с 2026 года версия — это `<год>.<дроп>.<хотфикс>`.
`1.21.11` стала последней версией «старой» нумерации, дальше идут `26.1`, `26.1.1`,
`26.1.2`, `26.2`, … Снапшоты называются `26.1-snapshot-1` и т.д.

Следствия для загрузчиков:

* **NeoForge** повторяет номер игры: `21.1.x` → MC 1.21.1, `21.11.x` → MC 1.21.11,
  `26.1.2.x` → MC 26.1.2, `26.2.0.x` → MC 26.2.
* **Forge** продолжает свою сквозную нумерацию: `47.x` → 1.20.1, `52.x` → 1.21.1,
  `65.x` → 26.2.
* **Fabric API** версионируется как `<номер сборки>+<версия MC>`, Loader и Loom —
  независимо от версии игры.

## 4. Деобфускация и маппинги (важнейший водораздел)

| До 1.21.11 включительно | С 26.1 |
|---|---|
| Игра обфусцирована | Игра поставляется с настоящими именами |
| Доступны Yarn, Mojang mappings, Parchment, Intermediary | Только официальные имена (+ Parchment для параметров, где есть) |
| Loom-плагин `net.fabricmc.fabric-loom-remap` | Loom-плагин `net.fabricmc.fabric-loom` |
| В Fabric-зависимостях `modImplementation` | Обычный `implementation`, ремаппинг не нужен |
| Мод собирается в intermediary и ремапится | Мод собирается сразу против финальных имён |

Yarn и Intermediary официально **перестают обновляться после 1.21.11** — Fabric прямым
текстом рекомендует переводить моды на Mojang mappings заранее, тогда переезд на 26.x
сведётся к правке build-скрипта.

## 5. Что выбирать под задачу

| Задача | Версия и загрузчик |
|---|---|
| Мод для крупного модпака 1.21-эры | 1.21.1 + NeoForge (при желании ещё Fabric) |
| Лёгкий клиентский/оптимизационный мод | Fabric, актуальная версия (26.2) |
| Поддержка старых модпаков | 1.20.1 + Forge |
| Новый проект «на вырост» | 1.21.1 (LTS) и параллельно ветка 26.2 |
| Экспериментальный мод под снапшоты | Fabric — обновляется быстрее всех |

## 6. Как обновить эту таблицу

```bash
./tools/check-versions.sh          # печатает свежие версии из maven/промо-эндпоинтов
./tools/sync-templates.sh          # пересобирает templates/ из апстрим-шаблонов
```

Если версии в апстримовых шаблонах отстают от maven, правьте пины в
`tools/sync-templates.sh` (секция `VERSION PINS`), а не сами шаблоны — иначе
следующая синхронизация затрёт правки.
